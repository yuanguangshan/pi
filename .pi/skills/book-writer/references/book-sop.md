# 分章撰写 SOP（pi 版）

本文件是 SKILL.md 的详细补充，在并行写多章、修订章节、整合书稿时加载。

## 1. 单章节任务输入

写每章前明确以下内容：

- 任务: 撰写《<书名>》第 N 章 "<章节标题>"
- 必读: BRIEF.md（风格/术语/事实）、OUTLINE.md（该章定位）、materials/ 相关素材
- 交付: chapters/chNN_<标题>.md，8000-10000 中文字符（不含英文/数字）
- 约束: 全角中文标点、BRIEF 概念词典、引用素材标注来源
- 写后自检: punctuation_check.py + chapter_wordcount.py

## 2. 修订 vs 重写

| 场景 | 动作 | 命名 |
|---|---|---|
| 局部修改 | 直接修改 | 保留 chNN.md |
| 全文重写 | 新文件 | chNN_标题_v2.md |
| 章节标题修改 | 修改 + OUTLINE.md 同步 | 保留 chNN.md |

定稿章节（已落盘并汇报）不再原地改写。

## 3. 并行策略

- 总章节 ≤ 5 章: 全部并行（并行工具调用或 subagent）
- 5 < 章节 ≤ 10: 拆 2 批
- > 10: 拆 3 批，每批后主控 mid-check

并行前提: BRIEF.md 必须写好；每个写作任务完整继承 BRIEF；写完后各自跑标点体检，主控收齐后再跑一次总检。

### 3.1 章末跨章钩子禁令（并行安全）

并行生成时，每章独立成篇，章末不得写"下一章将……""后面会讲到……"等跨章钩子——下一章内容在写作时不存在，写了必然断链。规则：

- 章末自然收束：小结、回扣本章核心论点，或留一个开放问题（不指向具体章节）。
- 确需提示后续内容时，用中性表述（"相关内容在后续章节展开"），不引用具体章节号/标题。
- 全书整合（Phase 6）后如需补跨章过渡，由主控统一在收尾时处理，不要求各章自行承担。

## 4. 主控收齐后必做

1. 对所有章节跑一次 punctuation_check.py（可传 chapters/ 目录）
2. 跑 chapter_wordcount.py chapters/ 确认每章达标；参考区间惩罚与评级，评级为"贴边"的章节（惩罚 ≥40）建议充实（至 8500+）或精简（至 9500-）后再定稿
3. 比对每章子节与 OUTLINE.md 是否覆盖
4. 未达标自动补做（最多 2 轮），结果写 _decision_log.md

## 5. 决策日志格式

```markdown
## [<时间戳>] <阶段> - <决策类型>

- 输入: <做了什么 / 评估什么>
- 决策规则: <SKILL.md 哪个决策门>
- 结果: <通过 / 未通过 / 自动修补 / 例外>
- 动作: <下一步>

---
```

每章记录"人文锚点"来源：真实人物标注素材文件名；文学化重构标注"文学化处理"。

## 6. 全书整合顺序

1. 书名标题块
2. 作者 + 完成时间
3. 序言全文
4. 目录（从 OUTLINE.md 生成）
5. 第 1 章 → 第 N 章（严格按 OUTLINE.md 顺序）
6. 后记 / 致谢（可选）

整合时不修改章节内容。
