# book-writer — 中文写书工程化技能

## 核心使命

把"写一本书"这件原本依赖灵感、容易跑偏的创作行为,工程化为一条可重复、可追溯、可被反复调整的流水线:

```
搜资料 → 共享资料包 → 大纲(AI 决策门) → 分章撰写 → 标点体检 → 章节双备份
                                                              ↓
                                          微信通知 ← 序言+整合 ← 全书完成
```

关键设计原则:
- **写即持久化**: 写完一章立刻双备份,不在内存里堆任何未保存的中间产物
- **标点硬约束**: 中文标点六项体检是不可跳过的关卡,不是可选项
- **共享资料包先行**: 多章节并行时,`BRIEF.md` 是统一规范避免各章风格漂移的最有效工具
- **🤖 全自动优先 (v2, 2026-08-09 修订)**: 默认**不打断用户**。BRIEF/大纲/章节标题/核心论点全部由 AI 自决,决策结果写入 `_decision_log.md` 留痕,用户事后可翻阅。**用户主动说"暂停""确认""调整"才进入交互模式**。

## 你的工作方式

本书的产出走七阶段流水线。**每个阶段都有"AI 决策门"和产出物,用户不参与**;只有 AI 自己判定不达标时才回退补做(同样写日志,不打搅用户):

| 阶段 | 动作 | 产出物 | 决策门 |
|---|---|---|---|
| 1. 资料搜集 | `search(web/kb/note)` 并行检索,落盘到 `materials/` | `materials/*.md`(可双备份) | 覆盖度自评 ≥ 阈值(默认 ≥ 80%) |
| 2. 大纲规划 | AI 直接生成章节标题、子节大纲、字数分配 | `OUTLINE.md` | 子论点可证伪性自检通过 |
| 3. 分章撰写 | 每章 ≥ 8000-10000 字,边写边 self-check | `chapters/chXX_标题.md` | 单章节成稿 + 标点六项全过 |
| 4. 标点体检 | 跑 `punctuation_check.py` 修到全过 | `punctuation_report.md` | 六项全部通过 |
| 5. 章节双备份 | 调 `dual_backup.py`:ima KB + Knowly | 两条备份 URL | 双备份成功 |
| 6. 序言+整合 | 写序言,合并所有章节为完整书稿 | `序言.md` + `_COMPLETE_BOOK.md` | 总标点体检 + 字数达标 |
| 7. 微信通知 | 调 `notify_wechat.py` 推完成消息 | 微信推送回执 | 通知成功 |

**执行原则**:
- 每个阶段**不跳级**。AI 决策门未通过时,自动回退补做,**不询问用户**。
- 整个流程对用户零打扰。用户给完"帮我写一本关于 X 的书"后,只需等待最终微信通知。
- 所有决策点(BRIEF 覆盖度判定、大纲子论点可证伪判定、章节标题选择、修订方向选择)都写入 `_decision_log.md` 留痕,用户可事后回溯。
- 唯一会暂停的例外:**遇到硬阻塞**(详见 Phase 8 异常分支),如资料源全部不可达、标点体检无法修复、网络彻底断——此时才通知用户。

### 1.2 共享资料包 BRIEF.md(关键!)

为每个写书项目建立一个 **`BRIEF.md`**,作为后续所有章节写作的"宪法"。这是并行写多章时避免风格漂移的核心工程杠杆。

**`BRIEF.md` 必含字段:**

```markdown
# [书名] 共享资料包 BRIEF

## 核心定位
- 主题: 
- 目标读者: 
- 核心论点 / 一句话价值主张: 

## 风格基线
- 人称: 第几人称?
- 语气: 理性克制 / 激情 / 散文?
- 标点规则: 中文全角(必读 references/punctuation-rules.md)
- 章节结构: 每章[小节数]小节,每小节[字数]字,共[章数]章

## 概念词典
- 关键术语定义(各章必须一致):
  - 术语1: 定义
  - 术语2: 定义

## 关键事实清单(必引)
- 事实1: [来源]
- 事实2: [来源]

## 资料索引
- 素材1:materials/raw_xxx.md(L1-L30)
- 素材2:materials/raw_yyy.md(L40-L120)
```

> **`BRIEF.md` 是 subagent 并行写作时避免各章标点不一致、术语不一致、风格不一致的最有效工具。**

### 1.3 资料落盘


### 1.4 AI 决策门:覆盖度自评(替代原"用户确认门")

`BRIEF.md` 写完后,**不询问用户**,AI 自行评估:

```python
覆盖度评分 = (已覆盖的核心论点维度数 / BRIEF 中声明的核心论点维度数) × 100%
```

| 覆盖度 | 决策 | 动作 |
|---|---|---|
| ≥ 80% | 通过 | 写入 `_decision_log.md`,进入 Phase 2 |
| 50%-80% | 自动补救 | 自动发起第二轮定向检索(只对缺失维度),补完后再评估;最多 2 轮 |
| < 50% | 异常分支 | 写日志,**通知用户**(这是少数需要打扰的硬阻塞场景之一) |

**决策日志格式** (`_decision_log.md`):

```markdown
## Phase 1 - 资料覆盖度决策
- 时间: 2026-08-09 14:00:00
- 第一轮检索: web=12, kb=5, note=3 → 命中 20 篇
- 覆盖度: 18/20 维度 = 90% ≥ 80%
- 决策: ✅ 通过
- 进入 Phase 2
```

> 此日志对用户透明,事后翻书可知"我当时怎么决定的"。

## Phase 2: 大纲规划 → OUTLINE.md

把 BRIEF.md 展开为章节级大纲,**章节目标字数 8000-10000 字**。

`OUTLINE.md` 模板:

```markdown
# 《[书名]》大纲

总章数: [N]
预计总字数: [N × 9000]
预计写作轮次: [每章 1 轮]

## 第 1 章 [标题]
- 核心论点: ...
- 子节:
  - 1.1 [子节标题] — [字数] 字
  - 1.2 [子节标题] — [字数] 字
  - 1.3 [子节标题] — [字数] 字
  ...
- 引用素材:materials/raw_xx.md#L1-L200
- 引用的核心概念:[BRIEF 中规定的术语]

## 第 2 章 ...

(每章依此格式)
```

### 2.1 AI 决策门:子论点可证伪性自检(替代原"用户逐章确认门")

大纲生成后,**不询问用户**,AI 逐章自检:

```python
对每章核心论点做"可证伪性检验":
- 是事实判断/可观察现象吗? → 通过
- 是不可证伪的玄学/纯审美/纯情绪吗? → 不通过,改写为可证伪陈述
- 是否与 BRIEF 中核心论点呼应? → 通过
- 是否在已有的 1-N-1 章中已覆盖? → 若重复则合并
```

| 检验结果 | 决策 |
|---|---|
| 所有章节可证伪 + 互相独立 + 覆盖 BRIEF 核心论点 | ✅ 写入日志,进入 Phase 3 |
| 部分章节不可证伪 | 自动改写,改写后再自检(最多 3 轮) |
| 自动改写 3 轮仍未达标 | 写日志,跳过该章 + 标"⚠️ 弱论点"标签继续,微信通知中告知 |

**决策日志格式**:

```markdown
## Phase 2 - 大纲可证伪性决策
- 总章节: 9 章
- 可证伪通过: 7 章 ✅
- 自动改写后通过: 2 章 ✅
- 最终大纲章节数: 9
- 决策: ✅ 通过
- 进入 Phase 3
```

## Phase 3: 分章撰写

### 3.1 单章节工作流(六步走)

每章写作时严格走六步——**新增"每章现搜资料"是硬性步骤**:

```
1. 读 BRIEF.md + OUTLINE.md 该章定位(核心论点、子节、字数)
        ↓
2. 🔍 现搜该章主题资料 — search(web/kb/note) 一轮,
   (web 用 zhihu_global_search;知乎命中用 fetch_zhihu_article 抓全文),
   把命中段落到 materials/chXX_*.md(或追加到章节素材文件)
        ↓
3. 读 materials/ 该章相关素材段 + 全局素材
        ↓
4. 开始撰写(目标 8000-10000 字)
        ↓
5. 写完立即:python3 punctuation_check.py chapters/chXX.md
        ↓
6. 修补到六项全过 → 进入 Phase 4 双备份
```

> **为什么每章还要再搜一次?**
> - **无大纲入口**:Phase 1 搜的是"全局综述",但每章有自己的子主题,需要补搜。比如《Unix 压缩史》全局搜了"压缩算法综述",但写 ch06 xz 时仍要 search "xz LZMA Igor Pavlov" 才能写出深度细节。
> - **有大纲入口**:用户的 OUTLINE.md 是结构骨架,但用户不会替你搜资料。每章动笔前的现搜让你的内容"贴骨架而生肉",而不是用 BRIEF 编故事。
> - **通用收益**:即使全局搜过,章节级 search 还能发现新近事件、补充数据点、修正错误。
>
> 这条**不可省略**——省略会导致"内容单薄,全靠 BRIEF 推论"的失败模式。

### 3.2 并行加速(默认开启)

**全自动模式下,默认开启 subagent 并行撰写**。前提是:

1. `BRIEF.md` 必须已经写好
2. 每章的 brief 必须从 `BRIEF.md` 完整继承,不允许 subagent 自行决定风格
3. 子任务描述必须包含:章节目标字数、引用素材路径、必须遵守的 BRIEF 片段
4. 每个 subagent 写完都必须自己跑 `punctuation_check.py`,主控在收齐后还要再跑一次全局总检

**并发数决策**(AI 自决,默认):
- 总章节 ≤ 5 章: 全部并行
- 5 < 总章节 ≤ 10 章: 拆 2 批
- > 10 章: 拆 3 批,每批后主控做一次 mid-check

> 决策写入日志。如用户后续要"重做某章",用 `--chapter N --rerun` 单独重跑。

### 3.3 写作时的硬性规则(摘自 BRIEF.md)

这些规则在任何中文写作中都成立,必须严格遵守:

1. **中文用全角标点**: `"..."` → `"..."`,`...。` → `...。`,`,` → `、`(并列项),`(...)` → `(...)`,`<...>` → `《...》`,`--` → `——`
2. **代码块豁免**: ` ``` ` 包围的代码块内部允许英文标点
3. **句末标点**: 中文句子必须以 `。`、`？`、`！`、`……` 之一收尾,**不用英文 `.`**
4. **数学符号 / 英文专用**: 公式、英文专有名词、URL 等允许英文标点,但紧邻中文时必须切换回全角
5. **不混排**: 一句话里不要前句中文标点、后句英文标点

详细的标点对照表见 `references/punctuation-rules.md`,实现见 `scripts/punctuation_check.py`。

### 3.4 字数自检

```bash
python3 scripts/chapter_wordcount.py chapters/chXX.md
```

- 总字数 = 中文字符数 + 全角标点数(英文 / 数字不算)
- 输出:`章节字数报告(目标 8000-10000)`
- **字数弹性标准(v3.1)**:
  - 标准区间:8000-10000 字
  - 最低线:单章 ≥ 6000 字(可接受"近达标",仍需在决策日志标注原因)
  - 缓冲上限:≤ 11000 字(超出则精简)
  - < 6000 字:必须补写或拆分小节,不得带病进入备份

### 3.5 AI 决策门:章节质量门(全自动)

每章写完 + 标点六项全过 + 字数达标 → 直接进 Phase 5 双备份。**不询问用户**。

| 检查项 | 通过条件 | 失败动作 |
|---|---|---|
| 标点六项 | 全过 | 不通过则 file_edit 修补,再检;`--fix` 最多 2 轮,仍不过 → 标"⚠️ 标点瑕疵"接受(但不得进入 Phase 6 整合) |
| 字数 | 8000-10000(弹性见 3.4) | 不足 6000 则补写小节;超出 11000 则精简 |
| 子节覆盖 | ≥ 80% 与 OUTLINE.md 对齐 | 缺失则补齐缺失子节 |

> **任何决策都自动执行,只把"做了什么"写入日志。**

## Phase 4: 标点体检

每章写完后**必跑**(硬性关卡):

```bash
python3 scripts/punctuation_check.py chapters/chXX.md
```

输出体检报告 `punctuation_report.md`。AI 自动修补到六项全过(详见 `references/punctuation-rules.md` 的修复策略)。

## Phase 5: 单章节双备份

写完且标点体检全过后,**立刻双备份**:

```bash
python3 scripts/dual_backup.py \
  --file chapters/chXX_标题.md \
  --label "第N章/[章节标题]" \
  --book-name "[书名]"
```

`dual_backup.py` 会同时:
1. 上传到 ima 知识库 `yuangs/books/<书名>/chapters/`(通过 `ima-knowledge/scripts/upload_file.py`)
2. 上传到 Knowly 服务器(通过 `上传到knowly/scripts/upload_to_knowly.py`)
3. 输出两份备份的"成功回执 + 路径 / NAS 保存位置"

> **为什么必须每章都备份?** 写书是长时间高投入活动,沙箱可能重置、模型可能掉线。**写一章保一章**,任何时刻当前进度都已落地,不丢工。

`dual_backup.py` 接受可选参数:
- `--no-kb`: 跳过知识库,仅 Knowly(用户明确要求时)
- `--no-knowly`: 跳过 Knowly,仅知识库(网络故障时兜底)
- `--folder-id`: 指定 ima KB 中的子目录,默认 `yuangs/books/<book>`
- `--list --book-name <书名>`: 列出该书所有章节 + 备份账本
- `--invariant-check --book-name <书名>`: 校验关键不变量(见下节)

### 5.1 备份决策门(v3.1)

每次备份的结果都追加写入 `_backup_log.jsonl` 账本,并按下表决策:

| 结果 | 决策 |
|---|---|
| 双备份都成功 | 写入账本,进入下一章 |
| 任一通道失败 | 标记 `--no-knowly` 或 `--no-kb` **降级重试一次**(另一边不受影响) |
| 降级后仍失败 / 连续 3 次失败 | 进入 Phase 8 异常分支,写日志,通知用户 |

> **核心原则**: 任何单条通道失败都不应阻塞写作流水线——先降级保进度,再修通道。

## Phase 6: 全书完成判断 + 序言整合

### 6.1 全书完成判断

最后一章备份成功后,进行"全书完成度"判断:

```bash
python3 scripts/integrate_book.py --check \
  --book-dir book-projects/<书名> \
  --outline OUTLINE.md
```

输出全书的章节完成情况。**所有大纲列出的章节都已 Phase 5 备份成功**时,进入 Phase 7。

### 6.2 序言撰写(全自动)

序言必须包含:
- 这本书为谁而写
- 核心问题的提出与本书的回答
- 全书结构导览
- 与同类书的差异
- 写作动机与致谢

序言字数视书规模而定,**通常 2000-4000 字**,走与正文相同的标点体检 + 双备份流程。

### 6.3 整合完整书稿

```bash
python3 scripts/integrate_book.py \
  --book-dir book-projects/<书名> \
  --preface 序言.md \
  --outline OUTLINE.md \
  --output _COMPLETE_BOOK.md
```

输出 `_COMPLETE_BOOK.md` 结构:

```
# 《书名》

> 作者:[广山哥]
> 完成时间:[YYYY-MM-DD]

## 序言
(序言.md 全文)

## 目录
(从 OUTLINE.md 自动生成)

## 正文

### 第 1 章 [标题]
(chapters/ch01_xxx.md 全文)

### 第 2 章 [标题]
(chapters/ch02_xxx.md 全文)

...
```

整合完成后**双备份** `_COMPLETE_BOOK.md`(同 Phase 5)。

### 6.4 字数 + 标点总检

整合后的全本必须再跑一次标点体检:

```bash
python3 scripts/punctuation_check.py _COMPLETE_BOOK.md
```

AI 决策门:六项全过 + 总字数 ≥ 8000 × N 章 → 进 Phase 7。字数略欠则标"⚠️ 字数略欠"继续;标点未过则 file_edit 修补,`--fix` 最多 2 轮,仍不过则标"⚠️ 标点瑕疵"接受 + 微信通知中告知。

> 整合稿双备份前,先跑 `dual_backup.py --invariant-check` 确认 INV-2 成立(见下节)。

## 关键不变量(v3.1,全程守护)

写书全程任何时刻保持以下不变量,破坏即触发修复/异常分支:

```
INV-1: 工作目录的 chapters/ 文件数 == 已双备份的 chapter 数
INV-2: _COMPLETE_BOOK.md 存在 ⟹ 所有大纲章节已双备份
INV-3: ima KB 上能找到 yuangs/books/<书名>/ 下的所有 chNN 文件
INV-4: Knowly NAS 上存在对应 /knowly_data/<书名>/chNN 文件
```

```bash
python3 scripts/dual_backup.py --invariant-check --book-name "<书名>"
```

INV-1/INV-2 可本地校验;INV-3/INV-4 由每次备份的账本回执保证。整合稿备份前必查 INV-2。

## Phase 8: 异常分支(全自动模式下的"何时打扰用户")

**默认不打扰**。但以下 7 类硬阻塞必须通知用户(v3.1 融合两版场景):

1. **资料源全部不可达** (web+kb+note 三路同时失败) → 通知用户换主题或提供资料
2. **标点体检 `--fix` 2 轮后仍 > 10 处违规** → 通知用户"标点问题,建议人工介入"
3. **双备份连续 3 次失败** (两通道合计) → 通知用户"备份链路异常"
4. **网络中断 > 10 分钟** (ima KB + Knowly 都连不上) → 通知用户"网络异常,等待恢复"
5. **关键不变量失效** (INV-1/INV-2 破坏且无法自动修复) → 通知用户"目录结构异常,需修复"
6. **任何 fatal exception** (Python 崩溃 / OOM / 配额耗尽) → 通知用户
7. **可证伪性自检 3 轮未过** → 通知用户某章可能需要重写

所有异常处理都先**自动重试 2 次**,失败后才打扰。原则:**能自动解决的问题绝不打扰用户,只有硬阻塞才暂停**。

## 关键 SOP 速查(常驻规则)

| 场景 | 必做 |
|---|---|
| 启动写书新项目 | 先建 `book-projects/<书名>/` + BRIEF.md(AI 自决覆盖度) |
| 进入任何章节写作前 | 重读 BRIEF.md + OUTLINE.md 该章定位 |
| 每章写完 | 跑 `punctuation_check.py`,六项不过则不进入备份(AI 自决修补) |
| 每章备份后 | 永远不再修改 `chapters/chXX.md`(修改则视为新版本,需 `_v2` 后缀);账本核对 `dual_backup.py --check` |
| 整合前 | 必须所有章节都通过 Phase 5(状态查询:`scripts/dual_backup.py --check`)+ INV-2 校验通过 |
| 全部完成 | 必推送微信通知,即使 backup `dual_backup.py` 已经在终端输出 |
| 多章并行撰写 | subagent 必须自带 BRIEF.md 内容,主控必须收齐后跑一次总标点体检 |
| **全程决策留痕** | 任何 AI 自决都写 `_decision_log.md`,用户可事后回溯 |
| **用户不打断** | 默认不询问用户,仅 5 类硬阻塞例外(详见 Phase 8) |

## 不适用边界

- 单篇文章(用 `article-analysis`)
- 结构化报告(用 `ima-report`)
- 公众号长文 / 千字散文 / 不分章节的小文
- 翻译 / 校对已有书稿(走单独的翻译技能)
- 不需要双备份的临时写作
